# Как я проверяла задания тестами

Сначала я записала ожидаемое поведение классов в `tests/`, затем запустила
проверки и только после этого написала реализацию. История Git сохраняет оба
цикла «красный -> зелёный»:

| Задания | Коммит с тестами | Проверка до кода | Коммит с реализацией | После кода |
| --- | --- | --- | --- | --- |
| Студент, счётчик, итератор | `1898941` | 3 ошибки импорта: модули ещё не созданы | `e13eee2` | 14 тестов, OK |
| Товар и корзина | `250e911` | 14 тестов OK, новая группа не импортируется: нет `orders.py` | `e73c39e` | 23 теста, OK |

Обе ветки разработаны отдельно: `feature/core-classes` и
`feature/order-system`. В `main` они включены через `git merge --no-ff`, поэтому
порядок коммитов с тестами и реализацией виден в графе.

Команда проверки после слияния:

```sh
python -m unittest discover -s tests -v
```

Проверки не ограничиваются демонстрационными данными: для итератора есть
пустой и убывающий диапазоны, повторный `StopIteration`; для счётчика -
некорректный шаг без изменения состояния; для товара - точность копеек и
недопустимые цены; для корзины - объединение одинаковых товаров, удаление
части позиции, точная сумма и отсутствие изменений после ошибок.
